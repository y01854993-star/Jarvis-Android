# JARVIS Skill Hunter (اكتشاف المهارات)

بيدوّر على GitHub (بالـ API الرسمي) عن مشاريع تفيد جارفيس، يقيّمها، ويقترحها عليك. **مفيش تثبيت ولا دمج من غير موافقتك.**

## الدورة
1. **اكتشاف** (`skill-hunter.yml`): يومياً بحث خفيف (4 استعلامات بالتناوب)، وكل أحد بحث عميق. تقدر تشغّله يدوياً من Actions أو بالصوت "ابدأ بحث عن مهارات جديدة". 7 فئات: ذكاء، تحكم أندرويد، صوت، رؤية، هندسة برمجيات، أمان، أداء.
2. **تقييم آلي (بدون نموذج):** ترخيص (MIT/Apache/BSD..)، آخر تحديث، نجوم، archived/fork، الإصدارات، سكربتات التثبيت (`curl | sh` مثلاً)، صلاحيات الـ Manifest، `minSdk` مقابل تطبيقك (26)، هل هو مكتبة أندرويد. **أي رفض هنا نهائي** ومفيش نموذج بيلغيه.
3. **تحليل الفجوة (بنموذج):** بيقارن المشروع بقدرات جارفيس الحالية (`capabilities.json`): هل موجودة؟ هل الجديد أحسن (سرعة/تكلفة/أوفلاين/ثبات)؟ تكلفة الدمج؟ الملفات؟ الصلاحيات؟ الدرجة من 100.
4. **توصية:** اللي يعدّي الفلاتر ويجيب درجة ≥ 70 يتفتح له Issue بتقرير كامل.
5. **قرارك** بتعليق على الـ Issue من GitHub، أو من زراير لوحة **DISCOVER NEW SKILLS** (بتأكيد بضغطتين):
   - `/approve` يجهّز branch معزول وPull Request.
   - `/test` نفس الشيء كـ Draft.
   - `/info سؤالك` يجاوبك من بيانات المقترح.
   - `/reject` يرفض ويقفل.
6. **الدمج:** بعد الموافقة بينسخ المشروع للقراءة فقط (مفيش تشغيل لأي كود منه)، والنموذج بيقترح أقل تكامل، وبتتطبّق قواعد صارمة: مسارات محددة، اعتماد Maven فقط بصيغة صحيحة، صلاحيات `android.permission.*` فقط، **حظر** `Runtime.exec` و`ProcessBuilder` والتحميل الديناميكي للكلاسات، وإضافة إشعار الترخيص في `THIRD_PARTY_NOTICES.md`. بعدها بناء + اختبارات + تحقق من الـ APK (package id، `minSdk`، الصلاحيات ما اتشالتش) وبعدين Pull Request. **أنت بس اللي بتدمج.**

## الحالات
`DISCOVERED`، `UNDER_REVIEW`، `RECOMMENDED`، `AWAITING_APPROVAL`، `APPROVED`، `INTEGRATING`، `TESTING`، `INTEGRATED`، `REJECTED`، `FAILED`، `DEPRECATED`. التاريخ محفوظ لكل مشروع، ومش بيتقترح تاني إلا لو نزل إصدار جديد.

## أين البيانات
branch `skill-hunter-data` في الريبو (`skills.json`, `history.json`, `summary.json`). مش بيتدمج في `main` أبداً.

## الإعداد
1. ادمج الـ workflows في `main`.
2. Secrets: `ANTHROPIC_API_KEY` و/أو `GEMINI_API_KEY`. **بدون مفتاح نموذج: الاكتشاف والفلترة بيشتغلوا لكن مفيش توصيات** (الحالة `UNDER_REVIEW`).
3. فعّل Actions لإنشاء Pull Requests (Settings ← Actions ← General).

## حدود صريحة
- الفحص الأمني **heuristics ثابتة** على الوصف والـ README وسكربتات التثبيت والـ Manifest. مش فحص برمجيات خبيثة ومش ضمان أمان.
- مش بيقيّم تبعيات المشروع الفرعية ولا بيقرأ الكود المصدري كله.
- نجاح الدمج الآلي يعتمد على جودة النموذج؛ بوابات البناء والاختبار بتمنع PR مكسور، لكنها مش بتثبت إن الميزة شغالة صح على الموبايل.
- مفيش مهارة اتدمجت لحد دلوقتي.

## تجربة حقيقية (dry-run بدون نموذج)
4 استعلامات، 18 مشروع، تقييم 6، 18 طلب API فقط. اترفض: مشروع GPL، ومشروع من غير ترخيص واضح، ومشروع فيه `curl | sh`، وآخر محتاج `minSdk` أعلى من تطبيقك. ومفيش توصيات لعدم وجود نموذج، وده السلوك الصح.
